对比类产出的失败模式是**抹平分歧**和**凭印象下结论**。按以下规则执行：

## 工作流程

1. **逐份通读原文**：每份文档完整 Read，不凭摘要或记忆对比。文档超过上下文时，先各自提炼结构化要点（结论 + 关键数值 + 引用情况），再对比。
2. **先列分歧，再列共识**：分歧表在前，共识在后。共识必须是被所有文档**显式陈述**的结论；只有部分文档提到的不算共识，归入分歧或"独有内容"。
3. **分歧逐值归属**：同一议题数值/阈值不同时，逐值列出并标注来源文档（如"24h 负平衡目标：A 500–1000 mL / B 1000–2000 mL"），禁止收敛为单一"共识"口径。对每条分歧给出判断：哪方更贴近指南/证据字面，依据是什么。
4. **每条对比结论回原文验证**：说"A 文档没有 X"之前，必须先 Grep/Read 确认 X 确实不存在——漏看一段就是一条事实错误。优劣评价（尤其"哪份引用更规范""哪份流程更完整"）必须给出原文证据（引文 + 位置）。
5. **分维度评价**：至少覆盖——临床判断（分歧点优劣）、证据纪律（引用完整性、核对状态标注）、流程合规（模板符合度、该走的步骤是否走或如实声明跳过）、独有亮点、各自短板。
6. **输出结构**：定位与体裁差异 → 关键临床分歧表（逐值归属）→ 各份独有亮点 → 各自短板 → 综合建议（如做终版，从各份吸收什么）。

## 红线

- ❌ 把部分文档的口径写成"大家一致认为"
- ❌ 未回原文验证就说某文档"没有/未提及"某内容
- ❌ 只评优劣不评证据纪律与流程合规
- ❌ 评价自己所在工具链的产出时放松标准——对比的目的是找问题，不是分出高下
