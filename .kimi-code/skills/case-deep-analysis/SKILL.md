---
name: case-deep-analysis
description: 深度病例分析编排——对疑难 active issue（未明源休克、出血-血栓两难、难治 ARDS、Trousseau-DIC 等）执行"脱敏确认 → ima 证据检索 → 独立会诊交叉验证 → 模板化深度输出 → 引用-原文回核 → PHI 自检 → 归档"全流程
whenToUse: 某个 active issue 需要病因鉴别 + 风险评估 + 治疗策略的深度讨论时
---

按以下步骤执行，缺步要在输出中说明原因：

1. **脱敏确认**：检查输入是否含 PHI（真实姓名、身份证、手机、完整病案号、精确日期、单位）。若有，先提醒用户并替换为 P1/床号/病案号末 4 位/年龄段/入科第几天；规则见 `cases/README.md`。
2. **证据检索（准则类内容强制走 ima）**：分析中涉及指南推荐、剂量、阈值的内容，按 `ima-skills/kb-registry.md` 的检索顺序查 ima（自有「医学知识库」→ 订阅指南库交叉），遵守该文件的引用纪律（回原文核对、禁止凭记忆补全）；ima 无覆盖或 MCP 失效时才降级 WebSearch / 本地 `guidelines/`，并在输出中声明降级。
3. **独立会诊（疑难病例推荐）**：派 `icu-consultant` sub-agent 做独立评估，与主线分析交叉验证；结论分歧点如实呈现，不和稀泥。
4. **组织输出**：
   - rounds 段按 `cases/_templates/系统化-by-system.md`（神经/循环/呼吸/肾/感染/营养/血液/内分泌）
   - 深度决策段按 `cases/_templates/case-analysis.md`：需解决的问题 → 病例分析（编号问题，每条含最可能诊断 + 诊断依据 + 按可能性排序的鉴别 + 治疗策略分层）→ 关键试验速引表 → 参考文献
   - 风格底线：散文 + 要点，表只用于剂量/阈值速查；每条临床主张带行内 `[N]` 引用；关键试验首次出现用 `**TRIAL_NAME (Journal Year)**`
   - **先算后写（强制）**：凡输入数据可计算的指标（ROX、P/F、PBW、Vt、CrCl、driving pressure、AG/delta ratio、代碱代偿预期 PaCO₂、GIK/泵速换算、净超滤 mL/kg/h、校正钙）一律先用 `scripts/clinical_calc.py` 算出再动笔；**禁止"数据存疑所以无法计算"式跳过**——存疑时做区间/敏感性分析（如 ROX 按 RR 上下限各算一次）
   - **建议-证据对齐（强制）**：每条处置建议标注依据级别——`【指南原文】`（指南/共识字面推荐）、`【指南外推】`（从指南原则推导）、`【推理】`（生理/药理推理）。外推与推理必须显式写出依据链；推荐强度不得超过证据强度（如共识门槛之外的处置升级必须标注外推）。**`【指南原文】`标签必须附该指南/共识的原句引文（引号 + 节段/页码），没有原句引文就不许挂这个标签**——三次客户端复跑中两次出现把门槛外推误标为指南原文（C1 型错误），原句引文是让写者和回核者都能机械比对的唯一办法
   - **复查时机审视**：凡建议复查影像 / 内镜 / 穿刺等操作，须给出时机依据；对无依据的「常规复查」医嘱要主动质疑并给出推荐时间窗（如 AP 首周增强 CT 低估坏死范围、胰周穿刺宜待包裹形成）
   - 输出必备段落：需解决的问题 → 病例分析 → Active Issues → 24h plan → **Red flags（立即升级触发线）** → 关键试验速引 → 参考文献；完成后可跑 `python3 scripts/check_case_doc.py <文件>` 自查
5. **参考文献**：格式与标签按 `cases/_templates/references-style.md`；同一文献复用同一编号；禁止编造文献与剂量；每条剂量/阈值主张必须挂 `[N]`，每个 `[N]` 必须在文末列表中存在；**每条参考文献必须带核对状态标记（已回核 / 未核对原文 / 部分支持）**
6. **引用-原文回核（疑难分析必做）**：草稿完成后，派一个全新上下文的 sub-agent，拿「主张 + 引用编号 + 参考文献清单」逐条回 ima 原文/本地文件核对：①该引用是否真实存在、是否支持该主张、数字是否一致；②**对齐检查——每条建议的强度是否超出所引证据的字面范围**（如指南说"TG>11.3 才启动血液净化"，建议"平台期即追加"即属越界），越界者降级标注或改写；③**`【指南原文】`标签逐一与原句引文逐字比对**——主张的任何成分（门槛、时机、剂量、疗程）不在引句字面范围内的，降级为`【指南外推】`并补依据链。发现不支持或不一致的，修正后再进入下一步。
7. **PHI 双重自检**：写入前自检 + 写后提醒用户，逐项过 `case-analysis.md` 末尾清单。
8. **归档**：写入 `cases/YYYY-MM/`（按月目录），文件名体现主题与入科阶段（如 `P1-HTG-AP-D4-<主题>.md`）；**文件名禁止出现精确日期**（与 D 数组合可倒推入院日）。

**降级模式（仅在 sub-agent 派单实际不可用时启用）**：

⚠️ 触发前提（按顺序执行，缺一不可）：

1. **先尝试派单**。不要仅凭运行环境推断不支持——2026-10-15 探针确认 Kimi 桌面客户端装有 Agent 工具且注册了 `icu-consultant`。
2. **本项目已授予常设派单授权（2026-10-21 用户确认）**：步骤 3 必须实际派出 `icu-consultant` sub-agent 做独立会诊，步骤 6 必须实际派出全新上下文的 sub-agent 做引用回核。**无需再向用户要授权、不得因"运行指令按需派发"而停下询问**——本条款即视为用户的显式常设请求。
3. 仅当确认无 Agent 工具、或派单实际失败（工具报错/超时且重试一次仍失败）时，才走下方降级。

降级时步骤 3、6 改为单上下文执行，其余步骤不变：

- **步骤 3 降级**：初稿完成后，以「独立会诊医师」视角重新过一遍——只从原始病例数据出发重做鉴别诊断与风险评估，不沿用自己初稿的论证链；与初稿的分歧点如实呈现，不收敛、不和稀泥。
- **步骤 6 降级**：逐条核对「主张 + [N] + 参考文献清单」——引用是否支持主张、数字是否一致、主张强度是否超出证据字面范围；发现不支持或不一致的修正后再进入下一步。
- **强制声明**：输出中必须有「流程偏差说明」，写明「本次为单上下文降级执行，未经独立 sub-agent 交叉验证」。lint（`check_case_doc.py`）认可声明过的降级；**禁止静默跳过**。
